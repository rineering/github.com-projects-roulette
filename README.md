## Рулетка. Интеграция с DA

# Админка

Админка делится на три части: 
1. настройки для интеграции
2. настройка оформления и наполнение рулетки
3. кнопка запуска ручного режима (для обмена, например)

# Вывод через OBS
в OBS передается "главная" страница рулетки и проегрывается на триггере рулетки

# Интеграция
рулетка находится в режиме ожидания, и по хуку получает команду активироваться

#Терминология
Источник: Модуль получения событий из внешней системы.
Донат: Событие, полученное от одного из источников.
Донат-гол: Модуль, формирующий запросы на запуск при достижении заданной
суммы.
Источник запуска: Причина формирования запроса на запуск. Возможные
значения: Donation Goal, Manual, API.
Запрос на запуск: Внутренняя сущность, помещаемая в очередь.
Очередь: Последовательность ожидающих выполнения запросов.
Конфигурация рулетки: Совокупность настроек, определяющих состав наград,
правила их выбора и оформление рулетки.
Рулетка: Конфигурация, используемая при выполнении запроса.
Награда: Элемент конфигурации рулетки, который может стать результатом.
Результат: Информация о завершенном выполнении запроса.
Основная рулетка: Конфигурация, используемая по умолчанию.
Журнал донатов: Хронологический журнал всех полученных донатов.
Статистика донатов: Накопленная информация по каждому пользователю.
Журнал результатов рулетки: Хронологический журнал всех выполненных
вращений.
#Общие требования к системе
● Приложение состоит из независимых модулей.
● Каждый модуль выполняет только свою задачу.
● Все входящие события приводятся к единому внутреннему формату.
● Каждое событие содержит информацию об источнике.
● Все способы запуска используют единый жизненный цикл обработки.
● В приложении существует одна общая очередь запусков.
● Одновременно выполняется только один запрос на запуск.
● Очередь восстанавливается после перезапуска приложения.
● Пользователь может очистить очередь вручную.
● Приложение предоставляет достаточную информацию для диагностики работы в формате технических логов.

#Функциональные требования

Источники данных
● Поддерживаются DonationAlerts и DonatePay.
● Каждый источник реализуется отдельным модулем.
● Каждый источник приводит данные к единому внутреннему формату.
● Единый формат содержит информацию об источнике.
● Каждый донат записывается в журнал донатов.
● Повторная обработка одного события не допускается.
● Недоступность одного источника не влияет на работу остальных.

Донат-гол
● Стоимость донат-гола настраивается пользователем.
● Донат-гол использует сумму донатов всех источников.
● Один донат может сформировать несколько запросов на запуск.
● После формирования запросов сохраняется остаток накопленной суммы.
● Состояние донат-гола сохраняется между перезапусками.

Рулетки и очередь
● Приложение поддерживает несколько конфигураций рулеток.
● Одна конфигурация назначается основной.
● Все конфигурации используют единый виджет OBS.
● Одновременно отображается только одна рулетка.
● Все запросы проходят через общую очередь.
● Во время выполнения очереди любые последующие активации должны вставать в очередь, ручная активация должна быть заблокирована.
● Ручной запуск формирует запрос с пользователем Test.
● При аварийном завершении выполнение очереди продолжается после перезапуска.
● Изменение конфигураций и наград не должно нарушать работу приложения.

Требования к конфигуратору
● Пользователь может создавать, изменять и удалять конфигурации.
● Пользователь может назначать основную конфигурацию.
● Если существует хоть одна конфигурация, одна из них должна являться основной.
● Пользователь может настраивать состав наград.
● Пользователь может настраивать правила выбора наград.
● Пользователь может создавать шаблоны оформления.
● Пользователь может применять шаблоны оформления к другим конфигурациям.
● Рулетка должна поддерживать использование файлов оформления, созданных для кастомизации виджета рулетки DonationAlerts.
● Конфигуратор не допускает сохранение некорректной конфигурации.
● Приоритеты: защита от ошибок пользователя, интуитивность настройки, гибкость настройки.

Требования к API
● API обеспечивает простую интеграцию со Streamer.bot.
● API принимает запросы на запуск рулетки.
● API поддерживает выбор конфигурации рулетки.
● При отсутствии указания конфигурации запускается основная рулетка.
● API поддерживает передачу имени пользователя.
● API предоставляет полную информацию о результате, награде и конфигурациях рулеток.
● Недоступность API не останавливает работу приложения.
● При невозможности передачи данных выполняются повторные попытки.

Хранение данных
● Приложение ведет журнал всех полученных донатов.
● Приложение ведет статистику донатов по пользователям.
● Приложение ведет журнал всех результатов рулетки.
